# Support and uptime: OWNER ITEM O3, UNDECIDED

**Status:** no support or uptime commitment has been made, because none has
been decided. This file exists so the gap is visible rather than discovered
during a negotiation.

State only what will be honored. A commitment a two-person team cannot meet at
3am on a holiday is worse than an honest lower number, because the first
failure to meet it becomes the story.

## What is true today, stated without commitment

The application is a static shell on a CDN and a managed database; there is no
ReqPub-operated server to fall over. Availability in practice follows the
hosting provider's, which publishes its own status page and history.

Verification does not depend on ReqPub being up. A customer holding an
evidence pack can verify it with the published tool and openssl during a total
ReqPub outage, which is a deliberate property and should be said plainly in
whatever commitment is eventually made.

## Decisions required

# ReqPub webhooks

Outbound, signed, and inert until configured. A project with no endpoint
enqueues nothing and sends nothing. A manager adds an https endpoint on the
project's Access page; from then on, each configured event posts one JSON
delivery per active endpoint.

## Events

| event | fires when |
| --- | --- |
| `sign.signed` | a signature request transitions pending to signed |
| `sign.declined` | a signature request transitions pending to declined |
| `seal.issued` | an acceptance receipt is sealed |
| `seal.timestamped` | a receipt gains its first RFC 3161 timestamp (pending to single or dual) |

A receipt that later upgrades from one timestamp to two does not fire a
second `seal.timestamped`.

## Payload

The body is a single JSON object:

| field | meaning |
| --- | --- |
| `event` | one of the four event names |
| `deliveryId` | this delivery's id; your dedupe key |
| `occurredAt` | UTC, microsecond ISO 8601 |
| `projectId` | the project |
| `versionLabel`, `seq` | the version the signature request points at |
| `signRequestId` | the signature request |
| `receiptId` | on the two seal events |
| `docFingerprint` | the document fingerprint captured at send |
| `chainHead` | `{ seq, linkHash }` of the project's activity chain at enqueue time, or null before the first chained event |
| `signerName`, `signerRole` | as recorded on the request |

The payload never contains a sign token, an email address, or document
content. Endpoint URLs are visible to project managers only, and the audit
trail records the endpoint's host, not its full URL.

## Verifying a delivery

Every request carries three headers:

```
X-ReqPub-Key-Id: whk-1
X-ReqPub-Timestamp: <unix seconds>
X-ReqPub-Signature: <base64 Ed25519 over utf8(timestamp + "." + rawBody)>
```

Verify like this, and reject anything that fails:

1. Reject if `|now - X-ReqPub-Timestamp| > 300` seconds.
2. Fetch `https://reqpub.com/reqpub-keys.json`, find the key whose `kid`
   matches `X-ReqPub-Key-Id`, and import its `publicKeySpkiBase64`.
3. Verify the signature over the exact raw bytes you received, prefixed by
   the timestamp and a dot. Parse the JSON only after the signature passes.

Node, end to end:

```js
import { webcrypto } from "node:crypto";

export async function verifyReqPubWebhook(req, rawBody) {
  const ts = Number(req.headers["x-reqpub-timestamp"]);
  if (Math.abs(Date.now() / 1000 - ts) > 300) return false;
  const keys = await (await fetch("https://reqpub.com/reqpub-keys.json")).json();
  const entry = keys.keys.find((k) => k.kid === req.headers["x-reqpub-key-id"]);
  if (!entry) return false;
  const key = await webcrypto.subtle.importKey(
    "spki", Buffer.from(entry.publicKeySpkiBase64, "base64"),
    { name: "Ed25519" }, false, ["verify"]);
  return webcrypto.subtle.verify({ name: "Ed25519" }, key,
    Buffer.from(req.headers["x-reqpub-signature"], "base64"),
    new TextEncoder().encode(ts + "." + rawBody));
}
```

## Delivery semantics

At-least-once. Duplicates are possible; dedupe on `deliveryId`. Answer with
any 2xx within 10 seconds; the response body's first 200 characters are kept
for the manager's delivery log. Redirects are not followed.

A non-2xx or a timeout walks a retry ladder: 1 minute, 5 minutes, 30
minutes, 2 hours, 12 hours, then the delivery is marked dead. A manager can
redeliver a failed or dead delivery from the panel at any time. In this
release dispatch is lazy: ReqPub attempts delivery right after the flows it
runs (signing, sealing), and the panel's Deliver pending button sweeps
anything waiting, so a quiet retry may wait for the next visit rather than
firing at the exact ladder moment.

## What ReqPub refuses to dial

Endpoints must be https. Before every attempt the host is resolved and the
attempt is refused if any answer is loopback, RFC 1918, link-local
(metadata addresses included), CGNAT, unique-local or link-local IPv6, or a
v4-mapped form of any of those. URLs carrying credentials and localhost
names are refused outright. A blocked endpoint records a failed attempt and
walks the normal ladder to dead, so a misconfiguration is visible in the
delivery log instead of silent.

## Keys

`whk-1` is generated by `scripts/generate-seal-keys.mjs` alongside the
sealing key: the private half becomes the `WEBHOOK_SIGNING_KEY` function
secret and exists nowhere else; the public half is published in
`reqpub-keys.json` at the site root, which is itself timestamped by
`scripts/timestamp-keys.mjs`.

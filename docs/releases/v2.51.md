## Recorded adaptation under fail-closed rule 11

The spec reads that key issuance and revocation are logged via
log_activity and therefore chained. Keys are org-scoped, and org-level
activity rows carry no project and sit outside the per-project chain by
the frozen v2.47 design. Determination: issuance and revocation log at
org level, uncchained, pinned by a test that asserts exactly this;
proposals, being project-scoped, are chained and their chain verifies
after the write. The alternative, forcing org events onto some project's
chain, would falsify the chain's meaning.

## Production deploy record, 2026-08-03, live

migrations/0024_mcp.sql ran on production through the dashboard SQL editor, moved as
eight 4000-character base64 slices with a running length gate on every
append, 31,660 characters assembled and decoded to exactly 23,745 bytes
before anything executed. The first run failed on a check violation: the
origin re-add was refused because live comms rows carry origin update.
The DO block is atomic, so the failed attempt changed nothing.

The finding ran deeper than legacy data. schema.sql re-adds the comms
origin constraint a second time in the update-threads section without
agent, and the update-thread reply path writes origin update today. Two
failures were waiting: fresh installs would have refused agent
proposals, and the seven-value fix would have broken update-thread
replies on the next reply posted. The production violation caught both.
The constraint now carries the canonical eight in migrations/0024_mcp.sql and in
both schema.sql sites, order independent, and the backend suite asserts
update and agent together in the final constraint definition.

The mcp function refused to deploy from the editor with an opaque 400.
The management API, called from inside the dashboard session, returned
the bundler's words: Module not found ./core.js at index.ts line 27.
Two generator bugs: the import strip matched single quotes while the
source imports with double quotes, and core was appended at the tail,
after the first top-level use of APP_VERSION, so the paste could never
have booted. No prior gate executed the concatenation; the Deno bundler
was the first thing that tried. The source was transformed in place,
core inlined at the import site so every declaration precedes first
use, and the deploy answered 201: slug mcp, version 1, ACTIVE,
verify_jwt false. The generator is rewritten to produce that transform,
the regenerated paste equals the deployed content byte for byte, and
the scheme suite now asserts the paste carries no local import and
declares APP_VERSION before SERVER_INFO.

Live smoke, in order, all green. A throwaway key was seeded with

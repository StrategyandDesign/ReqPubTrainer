# RELEASE REPORT v3.2: The engineering seam release

Two engineering papers describe the pod that builds from this record: a
roadmap in which the specification is the source of truth and the test
suite is the agent's instruction set, and an SDLC paper in which humans
write specifications and agents compile them. Twenty four demands on the
record follow from them. Against 3.1.0, twelve were met, nine in part and
three not at all. This release closes the seam in both directions: the
baseline that goes out to the Planner and the Coder, and what the build
learns coming back as a proposal a person accepts.

## The discovery record

Five tables under one unnumbered heading, in both document shapes, each
printed only when it has a row so every existing document is byte for byte
as it was. Clearance records who approved the environment, the data and the
access, and refusals too. Ranked problems carry the mechanism, the priced
gap and the rank; the executive signs the baseline that holds the table.
Findings record what the floor showed against what was claimed, with the
contradicting source beside the claim. Control function constraints carry
an owner and an optional fit criterion, and a constraint with a fit
criterion is a test the suite carries. Release reviews record each build run
against the suite: the build reference, the baseline fingerprint it read, the
result, who accepted it. Permanent ids: CLR, RANK, FND, CON, REL.

Success metrics gain a baseline measure and a comparison method. Decisions
gain Concerns and Kind. Functional and non functional rows gain a test input
and an expected result; evaluation rows gain a grader and a pass rate. Claims
themselves stay where they were, in the discovery entries, and promote into
requirements; they now leave in the evidence pack as written.

## The handoff

requirements.json carries every table with its ids, the test columns, the
discovery record, the decisions, the commercial thresholds and the glossary.
acceptance.md lists inputs and expected results under each box, the
commercial thresholds, and every testable constraint as a box of its own.
CHANGES.md names changes on every id bearing table, per column, before and
after. A knowledge folder carries the baseline as an Open Knowledge Format
bundle, version 0.2: one concept file per row with typed YAML frontmatter,
an index.md of links by section, a log.md of the revision history under ISO
date headings, the fingerprint on every file, deterministic for an unchanged
baseline.

Signed handoff is a project switch on the Access page. With it on, the
implementation package and reqpub_get_baseline refuse a version no client
has signed and sealed; every baseline answer states sealed and sealedBy
either way, and a refusal carries its sentence through the MCP handler.
tools/spec-drift-gate.mjs is the pipeline step the pod copies: it reads the
signed baseline over MCP, compares its fingerprint with the committed
requirements.json, and fails the build on drift, on an unsealed baseline
when one is required, or on a project that refuses the read.

## The return

A release review is a row an agent may propose through reqpub_propose and a
person promotes. The dossier then reads from the record to the commit and
back: the baseline fingerprint the build pinned, the suite result, the name
that accepted it.

## The whole record, unbranded

evidence_gather gains the discovery entries and every Inbox entry with its
thread, as written, under the same leak rules the suite greps for: no token,
no address. discovery.json and conversations.json join the pack and the
close package. A record with a brand label carries the practice's name on
the cover, the sign page, the presentation link and the record of delivery,
and no ReqPub mark; the verifier line keeps the tool's name because a
verifier has to know what to run. The record of delivery accepts the data
URL logos the app stores, and prints the objective the record holds, which
it never did.

## Mechanical review

Three more readiness warnings: a non negotiable constraint with no fit
criterion, a problem taken forward with no mechanism or priced gap, and a
testable constraint outside the EARS shapes. Contradiction between two tests
stays a human review.

## What was measured

Migration 0031_handoff_and_export.sql, idempotent, with its ledger row; the
replay proof holds schema.sql and the thirty one migrations to one database.
Every backend suite that replays an older migration ends its stack with
0031. Audit clean, capabilities gate clean at 45 entries, schema parity
clean, eslint at zero errors. New checks in both chains; the recorded counts
in tests/COUNTS.json are the ones the suites produced on this release.

## Deploy

Apply 0031_handoff_and_export.sql to the project database first, then push.
Then redeploy all eight edge functions from the repository, each with the
JWT setting its header states. Six of them were found in production at a
build older than 3.0.1, still importing supabase-js on a floating major tag,
and walkthrough-image was deployed with JWT verification on, which returned
401 to every share reader's image request. Both are corrected by the
redeploy; no function changed behavior in this release beyond the mcp
refusal sentence and the version stamp.

## Left open

The interview companion in front of the Inbox is a separate repository.
Threads attached to a row rather than to the project, and the semantic
check that two tests contradict each other, stay on the gap list.
